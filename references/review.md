# 审查标准

用于审稿式自查，或 workflow 第 4 步的独立审查。只报告具体问题，不打分。每个问题都要能定位（节、段、行或原句），并给出可以直接执行的修改建议。

## A. 阻断问题（必须修改才能通过）

1. **违反 Spec 或 DoD**：违反 spec 中的约束、术语表或决策记录；大纲中某段的 DoD 没有满足。
2. **结论没有证据**：superior / significant / outperforms 等结论没有数字、实验或引用支撑；正文数字与 spec 或结果文件不一致。
3. **与实现不一致**：方法描述、公式、变量、超参数与代码或实验设置不符。能读到代码时要实际核对。
4. **引用有问题**：引用了 .bib 中不存在的 key；对文献的转述与 `.vibepaper/refs/` 中的笔记不符。
5. **术语漂移**：同一个概念用了多个名称，或符号前后定义不一致。
6. **命中禁用词**：出现 `ai_words.json` 中 level=avoid 的词，且不属于引文或术语用法。

## B. 建议改进

- `word_style.md` 第 4 节（去 AI 味）的其他项：机械过渡、夸张修饰、绝对化断言、僵尸名词、领域外行话、句式单调、缺少具体性（第 4.2–4.8 节）。
- `word_style.md` 第 1 节的写作原则，以及对应章节文件中的要求。
- **叙事**：全文是否按 spec 中选定的故事类型讲（对照 `story_types.md` 中该类型的骨架和检查清单）；钩子是否在摘要或引言第一页出现。
- **摘要**：逐条对照 `sections/abstract.md` 末尾的检查清单（句数、作用序列、方法名登场位置、数字与对比、结尾）。
- **引言**：逐条对照 `sections/introduction.md` 末尾的检查清单（段落功能序列、段间衔接、核心创新出现的位置、Figure 1 引用、贡献列表与实验的对应）。
- **正文各章**：对照 `sections/related_work.md`、`method.md`、`experiments.md`、`conclusion.md` 末尾的检查清单（相关工作是否按路线分组并逐组定位本文；方法是否为问题驱动的求解链、先直觉后公式；实验是否与贡献逐条对应、有机制实验与替代解释排除；局限是否具体到失效场景、根因和方向）。
- **取名**：标题和方法名是否符合 `naming.md` 的检查标准；方法名在全文（包括大小写）是否一致。
- **用词与风格**：对照 `word_style.md` 第 2.2 节的结论强度规则、第 5 节的风格参数和第 7 节的定稿前总检查清单。

## C. 阅读体验

站在第一次读这篇论文的审稿人角度，逐项检查，只报告有问题的项。各项的具体标准见括号中的规范。

1. **第一页**：读完摘要、Figure 1 和引言前两段，能否说出问题、缺口、核心想法和效果；钩子是否出现（`story_types.md` 第 3 节、`sections/introduction.md` 第 4 节）。
2. **预期与回应**：提出问题或大胆假设后，是否很快给出回应，悬念有没有拖过一段。
3. **过渡**：各节、各段的首句是否承接上文（`sections/introduction.md` 第 3 节的衔接手法）。
4. **认知负担**：是否先给直觉再给公式；段首是否有主题句；概念是否在首次出现处解释（`word_style.md` 第 1 节原则 7、13）。
5. **坦诚**：是否主动说明局限和适用边界，局限是否具体到失效场景和原因（`sections/conclusion.md`）。

## 输出格式

```

## 阻断问题
1. [位置] 问题描述
   原文：「……」
   建议：……

## 建议改进
1. [位置] 问题描述 → 建议

## DoD 核对
| 段落 | DoD | 状态（✅ / ❌） | 说明 |
|---|---|---|---|

## 阅读体验
- [维度] 问题 → 建议

## 需要用户补充的信息
- 例如：缺少的实验数字、无法确认的引用
```

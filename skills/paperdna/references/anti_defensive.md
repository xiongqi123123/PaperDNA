# 发布会原则：不写防御性论文

> 来源：改编自 [anti-defensive-writing-Skill](https://github.com/Adkid-Zephyr/anti-defensive-writing-Skill)（MIT，Copyright (c) 2026 Adkid-Zephyr），许可声明见仓库根目录 `THIRD_PARTY_NOTICES.md`。
> 定位：本文件是"如何对待不利结果、局限和自我评价"的唯一来源。其他文件与本文件冲突时，以本文件为准。
> 适用：写或改任何章节，压缩篇幅，组织实验，写 rebuttal 之前的自查。

---

## 0. 速查

| 事项 | 做法 |
|---|---|
| 总原则 | 论文是一场学术发布会，不是项目总结、实验日志或自我审查报告。围绕本文最值得发表的优势组织全部材料 |
| 不利结果 | 不主动示弱，不说输。按第 3 节的顺序处理：删、收缩主张、换口径、解释为取舍、重组、重构故事，最后才直接说明 |
| 局限 | **最多 2 条**，每条一两句，写成"适用边界 + 后续方向"；放在结论之前的 Limitations 段，或结论中间，不放在摘要、引言，也不作为全文最后一句 |
| 摘要与引言 | 只建立问题、缺口、方案、最强结果和意义，不提不足 |
| 结论 | 只强化记忆点：解决了什么、提出了什么、证明了什么、为什么重要，最后一句落在意义上 |
| 用词 | 不用自我削弱词（`ai_words.json` 中类别为"自我削弱"的条目，扫描脚本会标出） |
| 底线 | 数字和表格照实填写；文字里的主张不越过证据。做不到领先就收缩主张，不硬说 outperform，也不专门写自己输了 |

## 1. 什么是防御性写作

审稿人还没开口，作者先把"遗憾的是""效果有限""仍明显落后"写满全文；结构按"我们先做了什么、又试了什么"展开；结论最后一段突然自我否定。这等于提前把刀子递到审稿人手里。

| | 防御性写作 | 发布会原则 |
|---|---|---|
| 局限表述 | 虽然本方法在两个同领域数据集上提高了准确率，但必须承认，我们尚未测试跨领域泛化，因此应谨慎理解这些结果。 | 本方法在两个同领域数据集上提高了准确率；跨领域泛化尚未评估。 |
| 英文 | *Although our method improves accuracy on two in-domain datasets, we must acknowledge that cross-domain generalization remains untested, so these results should be interpreted with caution.* | *Our method improves accuracy on two in-domain datasets; cross-domain generalization is left for future work.* |
| 结构 | 我们首先尝试了 A，然后尝试了 B，最后选择了 C | 问题 X 很关键，现有方法缺 Y，本文提出 Z，证据如下 |
| 实验 | 附录式堆结果，全覆盖、无重点 | 每个实验承担一个论证职责 |
| 结论 | 最后一段突然自我否定 | 只强化记忆点 |

## 2. 叙事规则

1. **只围绕优势组织主线。** 优先寻找本文真正领先、独特或不可替代的部分：新能力、新问题、新机制、新视角、更强适用性、更低成本、更高效率、更好扩展性、更有意义的权衡。没有形成优势的内容，不进入主线。
2. **不写成工作汇报。** 只保留最终成立的逻辑：问题为什么重要 → 现有方法为什么不够 → 本文提供了什么 → 证据如何支持。叙事骨架见 `references/story_types.md`。
3. **打不过的维度，不设为比赛项目。** 某个指标不占优，就不把叙事建立在它上面。选择更能反映本文价值的任务定义、评价维度、应用场景、约束条件或比较口径，讲清本文赢的是哪一场比赛。换口径的前提是新口径确实是本文的目标；领域公认的基准结果仍然放进表格。
4. **优势必须明说。** 不要指望审稿人自己从表格里发现贡献。主动解释本文在什么条件下表现最好、优势为什么会出现、解决了什么实际问题（`references/word_style.md` 原则 1）。
5. **控制比较范围。** 不追求"所有数据集、所有指标全面领先"，只提出证据牢固支撑的主张。说服力来自主张与证据一致，不来自比较项目的数量。
6. **允许彻底重构故事。** 现有结果撑不住原始叙事时，不要围绕原叙事防守：重新定义问题、重排贡献、重选主结果，重做标题、摘要、引言和实验结构。故事服务于最强的证据，而不是忠于最初的设想。

## 3. 不利材料的处理顺序

遇到对本文不利的结果或事实，按下面的优先级处理，能在前一步解决就不走到后一步：

1. **删除**：与核心主张无关的内容直接删掉。
2. **收缩主张**：把 "outperforms all methods" 收缩为 "achieves the best results on 4 of 5 benchmarks" 或 "is competitive with X while being 3× faster"，避免无意义的正面对撞。
3. **换评价口径**：换成更能体现本文价值的维度（效率、泛化、鲁棒性、适用条件），前提见第 2 节第 3 条。
4. **解释为目标差异或合理取舍**：*"X targets offline accuracy, whereas our method is designed for real-time deployment."* 只在这个解释属实时使用。
5. **重组实验**：让优势成为表格、图和正文叙述的中心，次要结果移到补充材料。
6. **重构故事**：见第 2 节第 6 条。
7. **直接说明**：只有无法回避、并且确实影响核心结论时，才用一句事实性的话说明，不加情绪化修饰。

底线：
- 表格和数字照实，不删改、不挑选对自己有利的子集；领域公认的主指标照常报告。
- 文字里的主张不越过表格：本方法不是第一的格子，不在文字里声称领先（这时收缩主张），也不需要专门写一句"我们在这里不如 X"。
- 不编造解释。第 4 步的"目标差异"必须是真实的设计取舍。

## 4. 语言规则：不自我削弱

- **不用自我削弱词**：遗憾的是、必须承认、仍明显落后、效果有限、存在严重不足；*unfortunately*、*we must acknowledge*、*merely*、*only achieves*、*still lags far behind*、*limited improvement*、*severely insufficient*。这些词收录在 `references/ai_words.json`（类别"自我削弱"），扫描脚本会标出。
- **不说输**：不写"本文弱于""性能下降""未能超过"。先按第 3 节处理；必须提及时，用中性的比较措辞：*comparable to*、*competitive with*、*on par with*、*within 0.3 points of*。
- **不把局部现象上升为整体否定**：某个结果不构成优势时，不必提炼成结论，更不要替读者把它推广成对整个方法的否定。
- **不过度限定**：一个结论加一处限定就够了。"may potentially suggest"、"to some extent, it might be possible that" 这类层层叠加的限定语，读起来就是心虚（结论强度规则见 `references/word_style.md` 第 2.2 节）。

## 5. 局限怎么写

- **最多 2 条。** 挑与核心主张最相关、审稿人一定会想到的两条；其余不写。
- **写成"适用边界 + 后续方向"，一两句话**：
  - *"Our method assumes a calibrated camera rig; extending it to uncalibrated setups is a natural next step."*
  - *"We focus on static scenes; handling dynamic objects is left for future work."*
- **位置**：结论之前的 Limitations 段，或结论段中间。不放在摘要和引言里，不作为全文最后一句。
- **不写**：情绪化的自我评价（"我们的方法仍有很大不足"）；为了显得坦诚而罗列一长串不足；在局限里重新提起正文已经收缩掉的比较。
- 写法细节和例句见 `references/sections/conclusion.md`。

## 6. 实验规则

实验不是结果仓库，而是论证工具。每个实验必须承担下面至少一项职责：

- 证明核心方法有效；
- 证明优势来自关键机制；
- 证明方法在目标场景中有价值；
- 排除最可能的替代解释。

不能强化主线、容易分散注意力或引出无关争论的实验：删除、弱化、移到补充材料，或者重新设计。实验章节的组织见 `references/sections/experiments.md`。

## 7. 交稿前自查：不给审稿人递刀子

逐句检查：

1. 这句话是否无意中扩大了本文需要承担的责任？
2. 是否提出了一个本来没人要求回答的问题？
3. 是否把局部现象描述成了普遍缺陷？
4. 是否用了比证据更宽泛的负面判断？
5. 有没有按"我们做了什么"的过程在展开？
6. 有没有把不领先的指标设成了主战场？
7. 摘要前五句里，问题和贡献都出现了吗？
8. 结论里有没有突然的自我否定？全文最后一句是不是落在意义上？
9. 局限是否不超过 2 条，每条是否写成了"边界 + 方向"？
10. 扫描脚本在"自我削弱"类别下是否还有命中？

不主动制造审稿问题，不主动扩大攻击面，不主动替反方完成论证。

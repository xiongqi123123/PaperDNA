# 文献阅读与证据整理

目标是把一篇文献整理成写作时可以放心引用的笔记。笔记存放在论文仓库的 `.paperdna/refs/<citekey>.md`。

## 1. 获取文本

- 默认先提取文本：`python3 <skill 目录>/scripts/parse_pdf.py <pdf> --main-only -o <txt>`，再用 Read 工具读文本。文本已合并断行连字符，并用 "=== Page N ===" 标出页码；文本里的换行是排版换行，不是句子边界。
- 需要看 Figure 1、表格版式，或者核对公式、上下标、希腊字母时，用 Read 工具读 PDF 对应页（pages 参数，每次最多 20 页）。
- 文本提取失败（扫描件、乱码严重）时，改为直接用 Read 工具逐页读 PDF。
- 在线文献用网页读取工具获取；arXiv 论文优先读 abs 页的元信息，再读 PDF。
- 通读的顺序是：摘要 → 引言 → 方法 → 实验结果 → 结论。如果只是为了回答某个具体问题，可以只读相关部分，并在笔记中注明读了哪些部分。

## 2. 写笔记

- 按 `templates/reference_note.md` 填写。
- citekey：论文的 `.bib` 里已有这篇文献时，沿用已有的 key；没有时按"作者姓 + 年份 + 关键词"生成，并在笔记里附上 BibTeX 条目。BibTeX 只填从 PDF 或官方页面确认过的字段；不确定的字段（如 DOI、页码）留空并注明，不要编造。
- 引文（quotes）必须逐字摘录，并注明页码；数据点注明出自哪张表或哪张图。
- 区分"作者声称的"和"实验实际显示的"。

## 3. 沉淀

- 本篇论文要用的术语 → `.paperdna/spec.md` 的术语表。
- 跨论文通用的术语 → `profile/glossary.md`。
- 值得借鉴的写法 → 笔记中的"可借鉴写法"一节。只有用户明确要求学习这篇文献的风格时，才按 `references/style_extraction.md` 更新文风画像。
- 新的 BibTeX 条目：按第 5 节选定的引用方式写入论文的 `.bib`。

## 4. 汇报

向用户简要汇报：标题、作者、年份、一句话核心贡献、与本文的关系、笔记路径。

## 写作时使用证据

- 转述文献的观点或数字时，要能在对应的笔记里找到依据。找不到就回去读原文，或者标 `% TODO: verify`。
- spec 中列出的"必引文献"都要在正文中出现。

## 5. 引用方式

每篇论文用哪种方式处理引用，记在 `.paperdna/spec.md` 的"流程设置 → 引用方式"。

### 什么时候问

第一次用本 skill 写这篇论文（创建 `.paperdna/` 时），或第一次需要加引用时，如果 spec 里的引用方式还是空的，先停下来问用户选哪种，把选择写进 spec 和决策记录。之后不再问；用户要换，改 spec 即可。

### 方式 A：自动检索 + 独立核查

1. **检索**：需要引用时，自己检索这篇文献，不凭记忆写条目。
   - 找文献：Semantic Scholar（`https://api.semanticscholar.org/graph/v1/paper/search?query=<关键词>&fields=title,authors,year,venue,externalIds`，返回 DOI、arXiv id 和 DBLP key）、arXiv、Crossref、会议官网。DBLP 对脚本访问有人机验证，读不到就换别的来源，不要绕过。
   - 取 BibTeX：有 DOI 时用 `curl -sL -H "Accept: application/x-bibtex" https://doi.org/<DOI>`；CVF 论文（CVPR、ICCV、WACV）取 openaccess.thecvf.com 论文页上的 bibtex；只有 arXiv 版时用 `https://arxiv.org/bibtex/<arXiv id>`。取回后按 `.bib` 已有的 key 风格改 key。
   - 有正式发表版本时引正式版本，不引 arXiv 版。
2. **写入**：BibTeX 写进 `.bib`，正文插入 `\cite{}`。同时按第 2 节写 `.paperdna/refs/<citekey>.md`，至少读过摘要，"链接 / DOI"填检索到的来源。正文转述的观点或数字要能在笔记里找到依据。
3. **独立核查**：每写完一节（workflow 第 4 步审查之前），把本节新加的引用交给独立子代理核查。用 Agent 工具启动 general-purpose 子代理，prompt 模板如下：

   > 你是引用核查员，只核查，不修改任何文件。
   > 待核查的引用：`<citekey 列表>`。`.bib` 在 `<路径>`，正文在 `<路径>`。
   > 对每个 key：
   > 1. 自己检索（DBLP、arXiv、Semantic Scholar、Crossref、出版方页面），不要只信 `.bib` 里的链接，确认这篇文献真实存在；
   > 2. 核对标题、作者、年份、会议或期刊与 `.bib` 条目一致；
   > 3. 在正文中找到引用它的每一句，读这篇文献的摘要，必要时读原文，判断这句话对它的转述（观点、数字、方法描述）是否成立。
   > 每个 key 返回一个结论：通过 / 元数据有误（给出正确值和来源链接）/ 查无此文 / 内容不支撑（引原句，说明文献实际说了什么）。查不到就如实写查不到，不要推测。

4. **处理结果**：元数据有误的按核查员给的来源改正；查无此文的删掉条目和 `\cite{}`，改成 `% TODO: cite ...`；内容不支撑的改写句子使之与文献一致，或换一篇合适的文献，都不行就改成 TODO。改过的条目再核查一次。
5. **记录**：通过的条目在笔记的"链接 / DOI"后注明"核查通过 YYYY-MM-DD"。没有通过核查的条目不能留在正文里。

### 方式 B：Claude 指出，用户提供 BibTeX

1. **占位**：需要引用时不写 BibTeX，正文写 `\cite{TODO:<建议 key>}`，如 `\cite{TODO:li2022bevformer}`。它能编译，PDF 里显示为问号，不会漏掉。在这一句所在行的上一行加注释，写明要引哪篇和为什么：`% TODO cite: <标题>, <第一作者> et al., <会议 年份> — <引用理由>`。
2. **告诉用户**：每节写完汇报时列出所有 `TODO:` 引用：标题、作者、年份、会议、为什么在这里引、检索关键词或链接。能联网时先确认这篇文献存在再推荐；凭记忆推荐、没有确认过的，注明"未核实"。说不准具体是哪一篇时，描述需要什么样的文献，不要硬给一个标题。
3. **用户贴回 BibTeX 后**：原样写进 `.bib`（只修语法错误），用用户条目的 key 替换占位符，删掉那行 `% TODO cite` 注释。条目和推荐的不是同一篇时告诉用户。
4. 正文转述这篇文献的观点或数字时，照样要有笔记依据；没有 PDF 时请用户提供，或只写不依赖具体内容的引用。
